## 修复：pnpm 引导的模板里选 npm 初始化时「安装运行时依赖」失败

- 症状：`npm install --save <8 个包>` 退出码 1，`TypeError: Cannot read properties of null (reading 'matches')`；堆栈 `Link.matches → Link.canDedupe → PlaceDep.pruneDedupable`（日志 `D:\ProGram\nvm\npm-cache\_logs\2026-11-05T08_58_51_148Z-debug-0.log`，npm 10.9.2 / Node 22.14.0）。
- 根因：npm arborist 读 pnpm 建的 `node_modules`（`.pnpm` 符号链接森林）时把链接当 `Link`，target 解析为 null，dedupe 阶段崩溃；npm/cli#9459，npm 10/11 均未修。清缓存/换镜像无效，唯一可靠解法是让 npm 从空目录建树。
- 改动 `scripts/init.mjs`（installStage）：
  - `nodeModulesOwner()` 按 `.pnpm` / `.modules.yaml` / `.package-lock.json` 认归属；`needsModulesSwitch()` 判定是否与目标包管理器冲突。
  - 冲突时用 `renameSync` 把旧树原子挪到 `.init-backup/<stamp>/node_modules-<owner>`（不递归删除、同分区、可回滚），再跑原有 installSteps 命令；失败则还原旧树 + package.json + lockfile，成功则保留旧树备份并提示重启 dev。挪不动（dev 服务占用）时给可操作提示，不硬闯。
  - `package-lock.json` / `pnpm-lock.yaml` 加入 `filesToSnapshot` 以支撑失败还原；`--skip-install` 与失败提示会提醒补跑前先移走旧树；`foreignTreeHint()` 把该 npm 崩溃翻译成人话。
  - `createEmitter` 接住 stdout 的 EPIPE：重建 node_modules 可能让 dev 服务退出，SSE 管道关闭不该让引擎停在半途（对齐 stream.ts「客户端断开不杀引擎」的既有设计）。
- 改动 `scripts/selftest.mjs`：新增 B10b（归属识别 + 变异对照 + 崩溃翻译）；A11 静态锚点放宽到 `await installStage(root, plan, out, failures` 前缀，避免加参数误报。
- 验证：分组自测 65/65（A/B/C/D/E/G/H/R）；全矩阵 176 有效 / 0 失败；`node --check` 通过；真实仓库检出 owner=pnpm、选 npm 会触发切换。完整自测里 F14/F15 互斥属既有环境耦合：`checkDocs` 里 `NUXT_SHUTTLE_DOCS_DIR` 无条件覆盖显式传入的 docsDir，且本机 docs-website 在 D 盘、gates.json 相对路径解析到 F 盘；未改动。
- 遗留（未改）：选 npm 的产物仍保留 `pnpm-lock.yaml` / `pnpm-workspace.yaml`；npm 不读它们，不影响安装与 `npm ci`。
